# Windows 11 验收步骤

适用于 1.3.7-zh.6 Windows 11 x64 便携包。请先完整解压，保留所有 DLL。
自动检查验证进程、工程和界面逻辑；输入法候选窗口、显示缩放及与其他 Windows 应用的实际互通需要人工操作。
本轮修复常用功能 A01 至 A18，保留上一版 B01 至 B39 修复；逐项映射见 [审计修复记录](audit-fixes.zh-CN.md)。
以下步骤覆盖这些修复及文件拖放、启动路径、系统图像剪贴板、中断保存恢复等原生行为。
本清单尚未在 Windows 11 实机执行，勾选结果须以实际操作为准。
Windows Server CI 的通过记录不能替代本清单。

## 先收集版本与自动检查结果

应用能正常打开时，可选择“帮助 → 导出诊断信息…”；“打开诊断文件夹”指向 `%LOCALAPPDATA%\Compositor\Diagnostics`。
日志保留近期会话，最多 8 份、每份最多 256 KiB，不复制工程和图片。

只导出诊断：双击便携包内的 `Run-Diagnostics.cmd`，完成后自动打开结果目录。
此入口不要求安装 PowerShell 7 或 .NET，也不会更改 PowerShell 执行策略。
若应用无法启动，查看该结果目录内的 `export.log`；进程尚未初始化时可能无法生成诊断 ZIP。

运行完整检查：在解压目录打开 PowerShell，执行：

```powershell
& .\diagnostics\Test-Windows.ps1 -ApplicationPath .\Compositor.Desktop.exe
```

该脚本兼容 Windows 自带的 PowerShell 5.1，也可用 PowerShell 7。
它遵循本机的脚本执行策略；若策略禁止脚本，可先用上面的 CMD 入口采集诊断。
脚本默认创建 `%LOCALAPPDATA%\Compositor\Checks\run-时间-随机标识\`，记录：

- 应用版本、Windows 版本、系统架构与构建信息。
- 英文、简体中文各 18 种模式，共 36 次自动检查目标；记录窗口、菜单、快捷键和指针交互的截图与日志。
- 输入法接口、诊断机制、保存失败、未保存关闭保护、编辑事务、导入流程、恢复、剪贴板接口、外部文件入口及 `dialogs-check` 参数绑定的自动检查结果。
- 可选相机 RAW 依赖状态；缺失时显示警告，继续检查基础 PNG/JPEG 编辑。
- `results.json` 结果表、检查前的 `before-checks-diagnostics.zip` 和检查后的 `diagnostics.zip`。

检查前先导出已有日志，避免大量检查进程触发日志轮转，覆盖需要调查的上次运行记录。
自动界面检查使用临时配置，不改写日常的最近项目、快捷键、工具和语言设置。
剪贴板自动检查使用模拟接口，不改写真实系统剪贴板。

每次运行使用新目录。可用 `-OutputDirectory <新的目录>` 指定位置，已有目录会拒绝使用，避免混入旧结果。
这些步骤不会搜索用户工程或自动上传数据。诊断文件仍可能含错误消息中的文件路径，分享前应自行检查内容。

## RAW 依赖检查

完整检查脚本通过 `--native-dependencies` 调用实际 RAW 绑定，并把输出存为 `native-dependencies.log`。
若退出码为 `3`，`results.json` 会记录该项 `Passed=false`、`Required=false`，不影响其他检查的继续执行。
先检查包内文件是否齐全，再按需手动安装或修复微软
[Visual C++ v14 Redistributable（x64）](https://aka.ms/vc14/vc_redist.x64.exe)，重启应用后重试。
[微软官方说明](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170)
提供受支持版本与系统要求。工具不会自动安装组件。

依赖加载成功仅说明 RAW 原生库可以调用。还需用自己的 RAW 文件副本实际导入，检查色彩、方向及尺寸。
Linux 交叉构建不会据此宣称 Windows RAW 验收通过。

## 标准工程与主要流程

包内 `samples/Chinese-Acceptance/` 提供中文工程、导入素材、参考 PNG 和详细步骤。
先把整个样例目录复制到可写的测试文件夹，例如 `文档\Compositor 中文测试`，保留原样例作对照。
不同电脑的字体版本和回退字体可能影响字形与换行，不要求跨平台的中文渲染像素完全一致。

| 项目 | 操作 | 通过条件 |
|---|---|---|
| 启动 | 从完整解压的包启动；如有条件，在未装 .NET 的电脑再试一次 | 正常进入界面，无缺失运行时或 DLL 错误 |
| 打开与保存 | 打开样例 `.comp`，调整图层，另存到中文和空格路径；关闭后重开 | 图层、文字、可见性、位置与保存前一致 |
| 导入与导出 | 导入样例素材，调整位置，导出 PNG，与参考图对照 | 画布大小正确，图像与文字完整，没有缺字方框 |
| 撤销与恢复 | 修改图层位置、文字和可见性，执行撤销与重做 | 每步状态正确恢复，快捷键和菜单操作一致 |
| 输入法 | 用微软拼音输入中文，选词、回车提交、Esc 取消，继续输入英文 | 组词期间不误触快捷键，提交一次，取消不留下残字 |
| 文本编辑 | 中英混排，移动光标、框选、退格和删除；保存后导出 | 中文、组合字符和 emoji 不被拆坏；已知复杂排版限制见 README |
| 未保存关闭 | 多个标签分别修改，关闭整个窗口；先选择“保留”，再用 Ctrl+S 或另存保存后关闭；另以副本测试“放弃” | 每个未保存标签都得到确认；“保留”或关闭确认框保留所有编辑；仅全部选择“放弃”才丢弃并退出 |
| 保存失败 | 在测试副本上向不可写目标另存，再另存到可写目标 | 显示失败原因；原文件与当前编辑内容保留；重试可成功 |
| 应用内复制粘贴 | 复制图像或选区，在应用内粘贴并撤销 | 新图层内容与透明区域正确，撤销后恢复原状态 |
| 系统图像剪贴板 | 与其他 Windows 图像应用双向复制粘贴；再复制文本或清空剪贴板后重试 | 图像内容、尺寸和颜色正确；外部文本或空内容不触发旧图像粘贴；透明通道另与支持透明图像的应用核对 |
| 文件拖放 | 将含中文空格路径的图片、PSD/PSB、工程目录或 manifest 拖入；再混合拖入一个无效文件 | 工程按类型打开或导入；无效项不阻断后续项目；源文件仍在原处 |
| 启动路径 | 使用下面的命令传入多个本地路径，重复指定工程目录和其 manifest，再加入无效路径 | 有效项仍处理，重复工程不重复打开，失败有汇总；当前运行窗口不接收跨进程转发 |
| 语言切换 | 在“编辑 → 语言”切换中文和英文，重启 | 选择被保存，菜单、对话框和快捷键可正常使用 |

请勿用唯一的原始工程验证保存失败。macOS 往返兼容另用工程副本验证。

## 系统图像剪贴板细项

- 分别验证 Compositor 内部复制，以及其他应用到 Compositor、Compositor 到其他应用的图像复制。
- 与支持透明图像剪贴板的应用核对透明边缘；仅提供无透明通道位图的应用不保证保留透明度。
- 复制后正常退出 Compositor，在另一应用粘贴，检查系统副本是否仍可用。
- 复制图像后在另一应用复制文本或清空剪贴板，再回到 Compositor 粘贴，确认没有粘贴过期图像。
- 验证剪切后撤销，及异步粘贴期间切换标签、图层、关闭原文档、开始拖动或文字编辑时取消过期操作，不改动错误工程或并入其他编辑历史。
- 若系统剪贴板读写失败，记录提示和诊断；自动检查的模拟失败结果不能替代此处的 Windows 实际行为。

## 启动参数与拖放

在完整解压目录打开 PowerShell，用测试副本执行：

```powershell
& .\Compositor.Desktop.exe "C:\Compositor 测试\中文 工程.comp" "C:\Compositor 测试\导入 素材.png"
```

路径也可相对于启动工作目录。`.comp` 目录和其 `manifest.json` 属于同一工程；
PSD/PSB 新建未保存工程标签；普通图片加入当前工程，空窗口先创建工程。
测试多项目输入的顺序、去重和部分失败后继续处理。URL、远程存储项不在本地路径支持范围。

拖放使用复制语义，不移动或删除源文件。关闭确认期间拖放不得更改正在确认的工程。
没有自动文件关联注册或单实例参数转发，因此此清单不要求双击 `.comp` 自动打开，也不要求新进程将文件送入旧窗口。

## 中断保存恢复

仅在样例副本和独立测试目录上验证，保留原样例。
用测试环境中受控中断的保存事务，或已存在的真实中断事务候选，检查：

1. 重启后只提示存在候选，不自动覆盖原工程。
2. 从“文件 → 恢复中断的保存…”查看登记事务留下的有效候选，分辨“未完成的新保存”和“上次保存版本”。
3. 选择候选后指定全新目标路径，确认恢复结果可正常打开，图层与图片完整。
4. 用已有目标测试拒绝覆盖；核对原目标和候选原件保持不变。
5. 成功恢复的候选被标记；取消或恢复失败仍可再次尝试。
6. 其他实例持有目标工程锁时，读取/保存/恢复超过两秒应明确失败并允许重试；候选扫描跳过繁忙目标，释放锁后再次发现候选。

登记记录默认位于 `%APPDATA%\Compositor\Recovery`。
该功能没有定时自动保存，未曾触发保存的编辑、旧版未登记备份不属于自动发现范围；登记前中断或文件不完整时也可能没有恢复候选。
不要使用唯一的原始工程或含有其他未保存工作的大量窗口进行强制退出试验。

## 缩放与多显示器

分别在 Windows 显示设置中使用 100%、125%、150%、200% 缩放。
每次记录显示器分辨率和缩放比例，检查主窗口、文件对话框、文字面板及长中文菜单。
有多显示器时将窗口在不同缩放的显示器之间移动，再测试画布点击与输入法候选位置。

通过条件：按钮与文字没有截断或重叠，画布点击位置准确，输入法候选窗口靠近光标。
屏幕不足以显示某些窗口时，记录实际分辨率和截图，避免只描述“显示不全”。
